# 開発計画と決定事項

作業を別のセッションに引き継いでも迷わないよう、決まったことをここに記録します。

## 進め方の約束
- オーナーはプログラミング未経験。各ステップで何をしているか、初心者にもわかる日本語で説明する
- 作業の区切りごとに Git でコミットし、GitHub(`4wjpmkftzy-ui/Textrade`)へプッシュする
- セキュリティ(個人情報が他人に見えないこと)を最優先にする
- スマホで見やすいデザインにする

## 🚨 サービス名は変更予定
- 仮の名前は「Textrade」だが、**2021年に同名の大学生向け教科書フリマアプリが存在した**
  (株式会社Textradeが運営。アプリは終了済みだが、会社と `textrade.org` は存続)
- 商標・検索での混乱を避けるため、**公開前に名前を変更する**
- 新しい名前は、特許庁の商標検索(J-PlatPat)で確認してから決める
- 名前は `src/lib/site.ts` の `SITE_NAME` 1か所で管理している(GitHubのリポジトリ名は後で変更してもよい)
- ⚠️ ドメイン `textrade.app` を取得済みで、Resend の送信元(no-reply@textrade.app)にも使っている。
  名前を変える場合、新しいドメインを取るか、このドメインを使い続けるかをオーナーと決める

## サービスの全体像
立命館大学の学生の「授業まわり」を1つで完結させるサービス。

| 機能 | 使われる時期 | 役割 |
|---|---|---|
| 🗓 時間割・出席管理 | 毎週 | **最初の目玉機能**。利用を習慣にする(季節性の解消) |
| 📖 授業ページ(シラバス要約+口コミ+その授業の教科書) | 履修登録の時期 | 集客の入口(検索からも来てもらう) |
| 📚 教科書売買 | 学期初めと学期末 | 収益の柱(将来の手数料) |

### 共通の前提
- 学生同士の中古教科書マッチング。運営は場を提供するだけ
- 代金:**PayPay送金などで当事者同士が直接やり取り**(運営はお金に触れない=「形A」)
  - 出品時に支払い方法(PayPay/現金/応相談、複数可)を選べる
  - 受け取り時に支払うことをサイト上で推奨する
- 受け渡し場所はサイト側で指定・案内しない
- 大学のロゴ・校章は使わない。大学名は所属を示す目的でのみ表示
- フッターに「各大学とは関係のない、学生が運営する独立したサービスです」
- メールは登録確認など必要なものだけ。宣伝メール機能は作らない
  (本人が登録した「欲しい授業の教科書が出品されたら知らせる」通知は可)
- 将来:オンライン決済+手数料を追加できる設計(`transactions` テーブルを用意済み)
- **アカウント削除(退会)機能**と**ユーザーのブロック機能**を用意する(App Store の審査で必須)

## 決定事項
### 教科書売買
- 表示名:**ニックネームのみ**(他の利用者に見えるのはニックネームと大学名だけ)
- 本の状態:新品同様 / 書き込みなし / 書き込み少し / 書き込み多い + マーカー・線引きの有無
- 開示できる連絡先:PayPay ID、LINE ID、連絡用メール、自由記入欄
  (ログイン用メールアドレスは開示対象にしない)
- 最初の対応大学:立命館大学(`ed.ritsumei.ac.jp`)
- **キャンパスの区別**:登録時に「主に通うキャンパス」(立命館なら BKC / KIC / OIC)を選ぶ。
  教科書の一覧は同じキャンパスの出品を優先表示し、出品には受け渡しできるキャンパスを表示する
  (手渡しの取引はキャンパス単位で閉じるため)
- 通報機能を追加する
- **過去のテスト問題・レポートの売買は禁止**(利用規約にも明記)
- **受け渡し方法は選択式**:出品時・購入希望時に「手渡し / 郵送 / どちらでもOK」を選び、**双方の希望が一致した方法**で取引する
  - 手渡し:同じ大学の本人確認済みの学生のみ。「人の多い場所・明るい時間に」などの一般的な安全の注意を表示(場所の指定はしない)。代金は受け取り時に支払う。取引後の評価・ブロック・通報
  - 郵送:住所・本名を教えずに済む方法(営業所やコンビニでの受け取りなど)を案内する。先払い・未着のリスクは当面、注意表示と評価で抑止し、
    **将来のオンライン決済(代金を運営が一時的に預かる仕組み)で解決**する。これが手数料を導入するきっかけにもなる
  - 郵送でもキャンパスをまたいだ取引ができるが、**取引は同じ大学の学生同士に限る**(全国の誰とでも取引できるようにはしない)

### 授業ページ
- **ログインなしで閲覧できる**ようにする(入学前の新入生のため+Google検索からの流入のため)
  - 出品・購入・口コミ投稿・出席管理はログイン必須
- データ源は**学外向け(公開版)のオンラインシラバスのみ**。学内向けは使わない
  - 文章を丸写しせず、「テストあり」「レポート40%」などの**事実を要約**する(著作権への配慮)
  - アクセス間隔を空けて、大学のサーバーに負担をかけない
  - 要約はAIで自動化する想定
- 公開版シラバスで確認できた項目:担当教員名、曜日・時限・単位数、成績評価方法(種類と割合の表)、授業外学習の指示
  (教室名は未確認)
- 口コミは**選択式中心**(負担度5段階、出席の取り方など)。教員への誹謗中傷を防ぐため、自由記述は最小限+通報・削除
- 口コミを有料で隠さない

### SNS機能の方針
- **入れない**:友達の位置情報の共有、写真・動画の投稿
  - 理由:何のアプリかがぼやける/ストーカー・つきまとい等の安全リスク(セキュリティ最優先の方針に反する)/
    盗撮・いじめ等の投稿を1人では監視できない/動画の保存・配信でサーバー代が跳ね上がる/強い競合(whoo、NauNau、Instagram 等)/App Store 審査が厳しくなる
- **代わりに、授業に関係する安全なつながりを追加する**(出席管理が定着した後、2027年夏以降が目安)
  - 友達と空きコマを共有(場所ではなく**時間**の共有)
  - 同じ授業を取っている友達がわかる(本人が許可した友達にだけ表示)
  - 時間割を友達に見せる(見せる相手は自分で選ぶ)

### 時間割・出席管理
- 需要の根拠:教授に「自分が何回休んだか」を聞く学生が多く、教授側は「数えていないので自分で数えて」と答えている
- **最初に公開する機能**(シラバス取り込みを待たず、授業名を自分で入力する形で先に出せる)
- 授業を時間割に登録し、出席/遅刻/欠席をワンタップで記録
- 出席記録は**本人しか見られない**(RLSで制限)
- 大学のシステムとは連携しない(手動で記録)
- 差別化:シラバスの出席条件から「あと何回欠席できるか」を表示、口コミ・教科書出品と連動
- 見せ方は「サボれる回数」ではなく「**単位を落とさないための出席管理**」
- 最大の課題は「記録を忘れる」こと → 授業終わりの通知、開いたら今の授業がすぐ出るワンタップ、記録漏れのお知らせ、あと何回休めるかの表示
- 通知はWebプッシュ(iPhoneはホーム画面への追加が必要)→ App Store版で本格対応

### App Store / Google Play 版
- 今の Web のプログラムを包んでアプリにする(Capacitor などを想定)。Web・iPhone・Android を1つのプログラムで運営
- 「Webを包んだだけ」は審査で却下されやすいので、アプリならではの機能を入れる:
  出席の通知、ホーム画面ウィジェット(今日の授業・欠席回数)、カメラでのバーコード出品
- 審査で必須:アカウント削除、通報・ブロック、プライバシーポリシーのURL
- オーナーは **Mac なし(Windows)**。iPhone アプリの作成・提出は GitHub Actions のクラウド上の Mac で行い、確認は TestFlight
- 開発者登録は**個人名義**(App Store に本名が表示されることは了承済み)。将来法人化したら名義を会社へ
- 配信は**日本のみ**(EU で配信すると住所・電話番号の公開を求められる場合があるため)
- 費用:Apple Developer Program 年99ドル(公開の数か月前に登録)、Google Play 25ドル(1回)

### 複数大学への対応(今のうちに設計に組み込む)
- **大学ごとの設定を1か所にまとめる**:メールドメイン、キャンパス、時限の時刻、学期、シラバスの場所
  → 新しい大学はプログラムを触らず設定の追加で対応
- **シラバスの取り込みは大学ごとに差し替えられる「部品」にする**(1校あたり1〜3週間の作業)
- **授業ページは学生の入力でも成り立つようにする**(テストの有無・評価方法を選択式で回答)
  → シラバス取り込みが終わる前でも、出席管理・教科書売買・口コミは初日から使える
- 1校追加の目安:設定だけなら数日、シラバス取り込みを含めて2〜4週間(慣れるほど短くなる)

## 認証の流れ
1. 大学メール+パスワード+ニックネームで登録(未対応ドメインはDB側で拒否)
2. 確認メールのリンクで認証 → `user_private.university_verified_at` が記録される
3. 任意で、ログイン用メールを個人メールに変更(Supabaseのメール変更機能。確認メールあり)
4. 所属大学は最初の大学メールで決まり、ログイン用メールを変えても変わらない

- 「**公開する日**」と「**広める日**」を分ける。公開は準備ができたらひっそり、告知は**学生がキャンパスにいる時期**に集中

## 事業戦略メモ
### 勝ち筋
- メルカリと同じ土俵で戦わない。「**この大学の授業まわりなら圧倒的に便利**」を目指す
- 強み:手数料0円・送料0円(手渡し)、授業から探せる、学内で即日受け取り、同じ大学の本人確認済みの学生だけ
- 先輩の書き込み(重要箇所のマーカーなど)を価値として見せる
- やらないこと:教科書以外の商品、全国配送、最初から手数料を取ること

### 広げ方
1. オーナーのクラス → サークル・ゼミの先輩(出品者) → 自分のキャンパス全体
2. 授業ページのGoogle検索からの流入(人づてに頼らない入口)
3. 共有ボタン、紹介制度などサービス内の「広まる仕組み」
4. オーナーは BKC。まず **BKC で密度を作る**。KIC・OIC は友人が1〜2人なので、検索流入・全学サークル・出席管理(キャンパスに関係なく使える)で自然に広げる
5. 他大学(試験が落ち着いた後、2028年秋〜が目安)。**協力者がいる大学を優先**
   - 2校目の最有力:**慶應**(友人が多い、1・2年生が日吉に集中、就活企業の需要が高い)。
     外部公開用シラバスあり(`gslbs.keio.jp/pub-syllabus/search`)。公開版の項目(特に成績評価)と利用規程は展開前に確認
     注意:早稲田限定の Unima が隣接市場。運営は現地の中心人物1人に任せる
   - 関西の候補:同志社・龍谷・関西大学・京都産業・近畿・関西学院など(協力者の有無で決める)
   - 広げてよい基準の目安:立命館で登録率15〜20%以上、登録者の半数以上が毎月継続
- 集客が得意な仲間候補がいる。役割と期待を言葉にし、お金・株の話は本格的に組むときに書面で決める
  - **4月上旬の山場までに声をかけておく**(1人+開発担当で回るのは BKC で数千人規模まで)
- 起業経験のある知人に相談できる。紹介を頼むのは利用者の数字が出てから

### 収益の見込み(仮定に基づく概算)
- 当面は収益0円(形A)。公開後1年ほどは利用者を増やすことに集中し、取引件数などを記録する
- 1大学:年30万〜200万円程度(手数料・スポンサー広告・有料の便利機能)
- 10大学:年300万〜2,000万円程度
- 大きく伸ばすなら、最終的な収益の柱は就活・インターンなど「企業が学生に会うための費用」
- 利用者の個人情報を企業に渡さない

### 主なリスク
- 立ち上がりの「出品がないと人が来ない」問題 → 学期末に出品を貯めてから、学期初めに告知
- 季節性 → 出席管理で毎週使ってもらう
- 3回生後半の就職活動で運営の時間が減る → それまでに一緒に運営する仲間を作る
- 大学との関係 → 独立サービスであることを明記し、必要なら学生課へ事前に相談
- 口コミによる教員への誹謗中傷 → 選択式中心、通報・削除
